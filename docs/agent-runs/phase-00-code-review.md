# Phase 00 code review — core model and direct CLI slice

Reviewer: Fable (adversarial review agent), 2026-07-12.
Scope: everything named in the Phase 00 brief; spec v1.1 §1.5, §2, §3, §4.1, §6.1, §6.3, §8.1, §8.3, §9; ADR 0001.
Method: full read of `pyproject.toml`, `Makefile`, all of `src/arcavex/**`, `tests/**`,
`examples/hello-poster/**`, plus test-suite execution and 10+ live CLI probes with scratch
templates under `outputs-tmp/review/` (inputs only; no production code touched).

## Summary verdict: REMEDIATE

The foundation is genuinely good: kernel purity is mechanically enforced and holds, the
pipeline states match §2.3, diagnostics are structured with hints nearly everywhere,
rendering is byte-identical across processes, and the code is clean, typed, and documented.
But four P1s — all of the form "required Phase 0 behavior silently wrong" — block acceptance:
preview_data masks missing required variables (the known defect), `visible: false` nodes
render anyway, a missing image asset exits 5/ARC-INT-999 instead of 3/ARC-AST, and non-goal
template sections (`locales:`, `styles:`, format `patch:`) are silently ignored instead of
rejected. Each is a small, localized fix.

## Findings

Severity: P0 data loss/unusable · P1 required Phase-0 behavior wrong/missing · P2 meaningful

| CR-1 | **P1** | `src/arcavex/services/template/compiler.py:159-166` (`_build_context`) | **preview_data is merged into the context unconditionally, then data is overlaid.** A data file that omits a required variable therefore validates and renders silently using the preview value. **Evidence:** `validate examples/hello-poster/template.yaml --data outputs-tmp/review/missing-title.yaml --format square --json` → `ok: true`, exit 0; `render` with the same inputs → exit 0, produces a poster with the preview title "Hello Arcavex". Spec §4.1.2: missing variables are errors. The unit test `test_missing_required_variable_located` passes only because its template has **no** `preview_data` section — the suite has a blind spot exactly over this bug. **Fix:** merge `preview_data` only when `data is None` (direct preview use); when a data file is supplied, resolve required/default checks against data + declared defaults alone. Add a regression test: template with preview_data + data file missing a required var → `ARC-TPL-014`, exit 1. |
| CR-2 | **P1** | `src/arcavex/builtin/layout_anchors/solver.py:65-92`, `src/arcavex/kernel/ir/models.py:288-302`, `src/arcavex/builtin/backend_skia/backend.py:157-158` | **`visible: false` nodes render anyway.** The compiler parses `visible` into `CompiledNode`, but `LayoutNode` has no `visible` field, the solver never reads `node.visible`, and the backend's `_visible()` checks only `opacity > 0`. **Evidence:** rendered `outputs-tmp/review/invisible.yaml` (full-canvas red rect with `visible: false`) → center pixel `(255, 0, 0, 255)`. `visible` is a core Phase 0 node field (brief item 2, spec §3.1.1). **Fix:** skip `visible: false` nodes (and their subtree) in the solver, or carry `visible` into `LayoutNode` and honor it in the backend. ## What is verifiably right (kept short)

- Kernel purity: import-linter contract KEPT; verified file-by-file — kernel modules import only stdlib/pydantic/kernel.
- Determinism: cross-process byte-identical PNG (same sha256 in three renders across two processes); no wall-clock/randomness in the render path (the evaluator's `perf_counter` budget cannot affect output values); PNG carries no timestamps; atomic write via temp-file + `os.replace`.
- Diagnostics discipline: every diagnostic has code + hint; facade never leaked a raw exception in any probe (the failures above are wrong *codes*, not raw tracebacks).
- Expression evaluator: hand-rolled, no `eval`, correct precedence (verified `1+2*3`, ternary, short-circuit `and`/`or`, `not` binding), missing-variable and `| default()` semantics correct, exact-match preserves native types.
- Unit math verified by hand and by tests: `px→pt = px*72/dpi`, `mm→pt = mm*72/25.4`, percent-basis enforcement, 1/1024 pt quantization in layout.
- Anchor solver under/over-constraint errors fire correctly with node IDs (ARC-LAY-030/031, LAY-020).
- CLI/API agreement is clean; `--json`, `--quiet`, `--no-color` all behave; exit codes 0/1/3/5 verified live (4 unreachable — CR-5; 2 only via Typer's own usage errors).
